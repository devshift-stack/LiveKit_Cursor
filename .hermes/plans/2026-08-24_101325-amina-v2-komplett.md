```python
# src/amina/turns.py
from __future__ import annotations
import os

TURN_BS_THRESHOLD = 0.55  # höher = wartet länger; jederzeit Env

def turn_detector_threshold() -> float:
    raw = os.getenv("AMINA_TURN_BS_THRESHOLD")
    if raw is None or raw.strip() == "":
        return TURN_BS_THRESHOLD
    value = float(raw)
    if not 0.0 < value < 1.0:
        raise ValueError("AMINA_TURN_BS_THRESHOLD must be between 0 and 1")
    return value
```

`build_session` (TypedDict, keine erfundenen Kwargs):

```python
from amina.turns import turn_detector_threshold

return AgentSession(
    stt=...,
    llm=...,
    tts=...,
    turn_handling={
        "turn_detection": inference.TurnDetector(
            unlikely_threshold=turn_detector_threshold(),  # Scalar, nicht {"bs": …}

        "endpointing": {"mode": "dynamic", "min_delay": 0.5, "max_delay": 3.0},
```

### Task 5: Abheben korrekt (Skript + Agent) — der frühere Fehlpunkt

**Problem (belegt):** Skript dispatched den Agent **bevor** SIP `--wait` zurückkommt. Agent ist im Raum **während es klingelt**. `wait_for_participant()` reicht nicht — SIP-Teilnehmer existiert oft schon beim Klingeln. Docs: `session.start` / Begrüßung erst nach Answer (`sip.callStatus=active`). Offiziell Outbound: **Mensch zuerst**.

**5a Skript** — `scripts/call-cloud-pick-agent.sh` (und analog `call-live-gsm.sh` wenn gleiche Reihenfolge):

1. Raumname festlegen  
2. `lk sip participant create … --wait --timeout 90s` **zuerst**  
3. Bei sip_exit ≠ 0: **kein** Dispatch, Diagnose, Ende  
4. Erst dann `lk dispatch create --room $ROOM --agent-name …`

`--wait` bleibt. Das **ist** CLI für `wait_until_answered`.

Test: Kommentar + `rg` in einem kleinen Shell-Check oder `tests/test_call_script_order.py`:

```python

assert src.index("sip participant create") < src.index("dispatch create")
```

**5b Agent** — `src/amina/agent_soniox_v2.py`:

- `asyncio.sleep` **löschen**
- `on_enter`:
  - **Console** (kein remote / kein `sip.` Attribut): Opener wie bisher (lokal hören).
  - **SIP:** nicht sofort reden. Wenn `sip.callStatus` gesetzt und nicht `active`: warten (Events/`participant_attributes_changed`) bis `active` oder 90 s Timeout → dann nichts sagen, Job darf enden.
  - Wenn `active`: **kein** `generate_reply`. Mensch darf Halo sagen (Docs + User).
  - Watchdog 2,5 s ohne User-Turn: dann **ein** kurzer Opener (`OPENER_INSTRUCTIONS_SONIOX`).

Hilfsfunktion in `src/amina/outbound.py` (testbar):

```python
def is_sip_answered(attributes: dict[str, str]) -> bool:
    return attributes.get("sip.callStatus") == "active"

def should_auto_greet(*, has_sip: bool, answered: bool, user_spoke: bool, silent_s: float) -> bool:
    if user_spoke:
        return False
    if not has_sip:
        return True  # console
    return answered and silent_s >= 2.5
```

```python
# tests/test_outbound.py

assert not is_sip_answered({"sip.callStatus": "ringing"})

assert not should_auto_greet(has_sip=True, answered=True, user_spoke=True, silent_s=3.0)
assert not should_auto_greet(has_sip=True, answered=False, user_spoke=False, silent_s=5.0)
```

`session.start` darf in Console sofort bleiben. Cloud: nach Dispatch-nach-Wait ist der Callee schon `active` — dann nur noch „User zuerst / 2,5 s“.
